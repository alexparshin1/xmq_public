XMQ 1.0.0 is out. It is the first release under a compatibility promise: the extension ABI, the configuration keys and the control API stay as they are through 1.x. You can download it here.

Persistence that holds when the disk is slow

Two changes, one problem. The broker looked a connecting client's stored session up with a request that held a thread until Redis answered: with Redis syncing every write (appendfsync always) on a USB hard disk, 0.9.19 refused 32,000 of 40,000 connections. The lookup is asynchronous now and CONNECT completes when the answer comes - no refusals on the same disk.

And a message's persistence record waits 10 ms before it is written, and is never written at all if the message has been acknowledged by then. On that same disk, with every write synced: 40,000 persistent messages a second at 159 µs. 0.9.19 managed 1,500 a second.

TLS at the front

The thread counts behind auto are four send, six receive and four delivery. Decryption happens on the receive path, and the old counts - read from the core count - left point-to-point over TLS at 100,000 messages a second at 549 µs; at the new ones it is 273 µs, against FlashMQ's 254 µs. Fan-out on the bench is 1788 µs, FlashMQ 1807 µs. The trade is deliberate and not free: the plain-text scenarios give back 3 to 18 per cent.

Fixed

  • On Windows a client that failed the TLS handshake could bring the broker down - a port scanner on the TLS port was enough. The accepted socket was closed twice, the second time in a way meant for files; it is closed once now, on every platform.
  • MQTT client shutdown could clear a callback while it was running, or destroy the client before its receiver returned - a crash during reconnects and bridge rebuilds.

Smaller things worth knowing

  • xmq_server --set-password asks for the password at a terminal and does not echo it. From a pipe it reads standard input as before.
  • RPM packages install beside the standalone SPTK packages without conflicting .build-id links.
  • The Docker image no longer sets the administrator's password from XMQ_ADMIN_PASSWORD; set it with xmq_server --set-password.
