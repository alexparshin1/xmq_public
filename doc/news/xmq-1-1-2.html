XMQ 1.1.2 brings MQTT to browser applications over WebSockets and introduces four extra ways to integrate client authentication with existing infrastructure. Download XMQ 1.1.2.

  • MQTT over WebSockets. Browser applications can now connect directly to XMQ over WebSockets, without a separate gateway to translate MQTT traffic. Configure WS or secure WSS listeners alongside your existing TCP and TLS listeners.
  • Bind MQTT identities to client certificates. XMQ can require the MQTT username to match a selected identity in the client certificate and check certificate revocation lists on every new connection. These experimental checks are optional and do not replace existing authentication or topic permissions.
  • Sign in with LDAP or Active Directory. The LDAP extension lets MQTT clients use directory credentials and maps directory groups to XMQ groups, while the broker still controls topic access. The Active Directory profile supports nested groups and rejects disabled accounts.
  • Use tokens from your identity provider. The JWT extension verifies tokens locally, so a client login does not need a round trip to the identity provider. Token claims map users into existing XMQ groups, where the broker enforces topic permissions.
  • Connect your own authentication service. The HTTP authentication extension can ask your service whether to admit an MQTT client and which XMQ groups to assign it. The broker still decides which topics the client can use, without sending topic names to the service.
