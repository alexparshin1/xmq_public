XMQ 0.9.15 is out. Nothing in it changes how the broker moves messages: it is about where XMQ runs, who it runs as, and what it looks like on a machine nobody has configured yet. You can download it here.

FreeBSD

XMQ now builds and passes its test suite on FreeBSD, and ships as a native pkg(8) package with an rc.d service. The package carries everything it needs — six files, 8 MB, no ports tree and no compiler on the target machine.

A Windows installer that needs nothing else

The installer is now a bootstrapper that carries the Visual C++ runtime with it, so installing XMQ no longer requires a network connection or a separate runtime download.

Nothing ships with a password

The broker no longer carries credentials anyone could look up. It asks for an administrator password at first start and keeps its web interface on the loopback address until one is set, so an unconfigured broker cannot be adopted over the network. The cluster account's password is generated during installation instead of being a constant printed in the documentation.

The service runs as its own account

On Linux and FreeBSD the package creates an unprivileged xmq account and gives it only the directories the broker actually writes. Until now the service ran as root, which a process listening on a network has no reason to do.

Logs no longer grow without limit

The log is rotated daily and a week of archives is kept, configurable through logs_to_keep. This works on every platform, Windows included, where the external rotation tools the Unix world assumes simply are not there.

One fix worth naming

A subscription could be lost on reconnect. When a client reconnected while its previous session was still being torn down, a write that failed on the old connection closed whichever connection the session happened to be holding — which could be the new one, taking the subscription just made with it. It was rare, it looked like a client bug from the outside, and it is fixed.

Packages for Linux, FreeBSD and Windows are on the downloads page.
