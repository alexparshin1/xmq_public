XMQ 1.0.1 is a bug-fix release: no new features, five fixes that matter to anyone running a broker. You can download it here.

  • A subscriber that stops reading can no longer take the broker's memory with it. queue_limits is enforced now - messages, bytes and the in-flight window - where before max_size was read and ignored, which is the fix for the fan-out that took two Windows nodes to 16-17 GB and stopped both brokers.
  • A session restored after a restart accepts what follows its CONNECT. PUBACKs, SUBSCRIBEs and DISCONNECTs are processed instead of being discarded as arriving before CONNECT, so an acknowledged message is not delivered again after the next restart and a new subscription is not silently lost.
  • A configuration edit can no longer leave a broker that will not start. The file is validated before it is loaded and before it is saved, written through a temporary file and renamed, and a file that is still broken falls back to the last configuration that worked.
  • xmq_server --set-password returns instead of aborting or hanging. It printed its result while holding a console lock it had already taken, which is the deadlock behind the symptom.
  • Restoring persistent sessions at startup is about thirty times faster. Sixty thousand sessions now come back in 1.1 s instead of 31.7 s, because the per-session Redis reads are batched and pipelined rather than waited for one at a time.
