XMQ has been open source by licence since August, when it moved to the Mozilla Public License 2.0. As of this week it is open source in practice as well: the broker is developed in a public repository, github.com/alexparshin1/xmq_public, and every change is made there, in the open, from 0.9.18 on.

What is there

  • The whole broker — the MQTT server, the configuration interface, the command-line clients, the Windows and Linux packaging, the Docker image and the tests.
  • The load generator and every benchmark scenario. The numbers on the test pages were produced by code you can now read and run against any MQTT broker, including ours, on your own hardware.
  • The extension API and its samples, for anyone who wants to add an authenticator, an access-control scheme or an event observer without touching the broker's source.
  • The changelog, written for someone deciding whether and how to upgrade.

XMQ is built on SPTK, the C++20 library developed alongside it, which is open source under the LGPL. The networking, threading and database layers the broker runs on are all there to read too.

The repository's history starts at 0.9.18. Earlier releases are described in the changelog from 0.9.14 on; the development history before that stays where it was.

What does not change

The licence is the one XMQ has carried since 0.9.14. The MPL is copyleft per file: changes to XMQ's own source files stay open, while a product that merely includes the broker, or an extension that uses its published API and ships as a separate binary, can be licensed however its author chooses. Binary packages stay free to download, and nothing about how the broker behaves depends on where its source lives.

Taking part

Bug reports and questions are welcome in the repository's issue tracker, or by email to alexeyp@gmail.com. A report is most useful with the broker version, the platform and the part of the log around the problem — the broker now says, among other things, which signal stopped it and how much work is waiting in its queues.
