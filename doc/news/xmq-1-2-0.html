XMQ 1.2.0 reworks extension configuration in the web interface and gives the webhook a way to evaluate messages with SQL rules. It also maps topic namespaces on MQTT bridges. Download XMQ 1.2.0.

  • Data integrations. One extension can now be configured several times, each with its own settings set - for example, two message exports writing to two databases with different topic filters. The Extensions screen lists the named data integrations and opens a dialog to add another. Settings are stored in the shared configuration database, so renaming an integration never changes its durable queue identity.
  • Clearer extension settings and permissions. Extension configuration is split into three pages, with independent switches for loading an extension and for persisting its settings. Installed Extensions shows what is actually loaded, and topic permissions are managed in User Management. The old, redundant ACL editor is gone.
  • SQL rules for webhook messages. A sql_rule selects an MQTT topic filter, a typed predicate and JSON output fields. The webhook evaluates and renders the rule in its worker, without adding a database lookup to message delivery or changing log delivery.
  • Bridge topic mapping. Optional local_prefix and remote_prefix settings map topic namespaces in both directions. Existing bridges keep their topic names unchanged; bridge-to-bridge forwarding remains disabled.

XMQ 1.2.0 requires SPTK 5.6.22. See the changelog for the full list of changes.
